# 团队模式 · 重构 / 迁移

> 六个团队模式之一，只在命中时读这一个。

**适用**：大规模重构、框架/语言/版本迁移、模块拆分或合并、批量 API 替换、数百文件级的机械改动。

**不适用**：小范围整理（自己干）；重构目标本身还没想清楚（先去研究辩论，或产品团队定需求）。

---

## 机制建议：这一类最容易被误用团队

| 形态 | 机制 |
|------|------|
| 同一套改动要重复几十到几百次（升级 API、换导入路径、拆文件） | **动态 workflow** 或 **`/batch`**，不是 agent team。脚本能保证每个单元用同一套规则；5 个 teammate 各自理解规则会产出 5 种风格 |
| 改动需要跨模块协商共享契约（拆服务、抽公共层） | **agent team** |
| 两者混合（最常见） | lead + planner + verifier 用 team，机械批量部分交给 workflow |

---

## 角色

| 角色 | 载体 | 权限 | 可写范围 |
|------|------|------|---------|
| **lead** | 当前会话 | — | 共享文件、合并 |
| **planner（规划师）** | 自定义只读 agent 或 `Explore` | 只读 | 无 |
| **module-A/B/C owner** | `general-purpose` | `acceptEdits` | 各自模块目录，或各自 worktree |
| **verifier（验证者）** | `general-purpose` | `acceptEdits`（只写测试与基准脚本） | `tests/`、基准脚本 |

---

## 顺序

```
t1 现状分析与边界拆分（planner）
t2 建立验证基线（verifier）              ← 可与 t1 并行
t3 契约冻结 + 迁移步骤排序（planner → lead 确认）
t4 模块 A ‖ B ‖ C 并行重构（各自 worktree）
t5 逐模块回归对比（verifier）
t6 集成、共享文件收口、合并（lead）
t7 全量基线对比 + 回滚点确认
```

---

## 规则

1. **契约先冻结。** planner 产出模块边界、对外接口、共享类型、迁移步骤与顺序、回滚点；定稿后冻结，模块 owner 只读引用，要改走 lead。并行的前提是接口稳定，否则每个模块会按自己的理解长出不同的形状。
2. **每个模块独立 worktree。** agent team **不会**自动隔离 teammate——用 `isolation: worktree` 或手动开 checkout。理由不只是防冲突：某个模块要推倒重来时，能单独丢弃它的工作树。
3. **行为不变是验收标准。** 重构的定义是不改外部行为。verifier 在动手**前**建立基线（测试全绿 + 关键路径的输出/性能快照），改完对比。没有基线的重构无法证明它没弄坏东西。
4. **小步提交，每步可回滚。** 每个 owner 按规划的步骤分批提交，不要攒一个巨型 commit。
5. **机械改动交给脚本或 workflow，不要交给「理解力」。** 能用 codemod 完成的部分（重命名、导入路径、API 替换）写成脚本一次跑完；agent 只处理脚本处理不了的判断部分。这比让 5 个 agent 各自手工改快得多，也一致得多。
6. **共享依赖变更要广播。** 某个模块需要改公共类型或工具函数时，先通知 lead 和其他 owner，由 lead 统一改并广播。
7. **不要一次迁完所有模块。** 先迁一个最小但有代表性的模块，验证规则与脚本，再扇出到其余模块。第一个模块是探针，不是负担。

---

## 规模

3–6 人。模块数决定 owner 数，但**并行 owner 不要超过 5 个**——lead 的协调能力是瓶颈，超过就分批做。

---

## 常见失败

| 症状 | 处理 |
|------|------|
| 各模块长歪，接口对不上 | 契约没冻结就并行；t3 是硬前置 |
| 说「重构完成」但没人能证明行为没变 | t2 基线是硬前置，t7 做全量对比 |
| 共享文件被多人改，合并冲突成片 | 共享文件归 lead；owner 提示词写死禁区 |
| 巨型 commit，出问题无法回滚 | 规则 4：小步提交 |
| 机械改动让 agent 手工做，慢且风格不一 | 规则 5：codemod / workflow |
| 5 个模块产出 5 种代码风格 | 用 workflow 或脚本统一规则，而不是靠 5 个人各自理解 |
