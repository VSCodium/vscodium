# README

README 是项目的门面，读者多半是第一次来，只想在几分钟内回答三个问题：这是什么，跟我有没有关系，怎么跑起来。写的时候照着这三个问题排优先级，其余内容能链接出去就链接出去。

## 先判断是哪种 README

| 类型 | 重点 | 通常不需要 |
|---|---|---|
| 应用 / 服务 | 怎么在本地跑起来、依赖哪些服务、有哪些环境变量、端口 | 安装到别的项目里的说明 |
| 库 / SDK / CLI | 安装、最小可用示例、主要 API 或命令一览、兼容版本 | 部署说明 |
| monorepo 根目录 | 仓库是什么、子包地图、公共命令、去哪里找每个子包的文档 | 每个子包的细节 |
| monorepo 子包 | 这个包在整体里的位置、自己的启动与测试命令、和其他包的依赖 | 重复根 README 的通用说明，链接回去即可 |

monorepo 子包的 README 开头写一句它在整个仓库里是干什么的，并链接到根 README；公共的安装步骤不要再抄一遍。

## 新建 README

### 动笔前核实

- 项目名称和一句话定位：从 manifest 的 `name` / `description`、入口代码、已有文档里找。
- 运行时和版本：`engines`、`.nvmrc`、`.tool-versions`、`go.mod`、`pyproject.toml` 的 `requires-python`、Dockerfile 的 `FROM`。
- 命令：只写 `package.json` 的 `scripts`、`Makefile`、`justfile`、CI 配置里真实存在的。能跑的最好跑一下安装和启动命令确认；跑不了就不要编造输出。
- 环境变量：`.env.example` / `.env.template` / `.env.sample`，以及代码里读取环境变量的位置（`process.env.X`、`os.getenv`、`env.X` 的配置模块）。以代码实际读取的为准，模板里有但代码不用的，不写或注明。
- 端口、依赖服务（数据库、Redis、消息队列）：从配置文件、docker-compose、启动脚本里找。

### 章节结构

按顺序，缺的就不写，不要为了完整留空章节：

1. **标题 + 一两句话**：是什么、给谁用、解决什么问题。不写口号。
2. **快速开始**：前置条件（带版本）→ 安装 → 配置 → 启动 → 怎么确认跑起来了（打开哪个地址、看到什么输出、调哪个健康检查接口）。每一步是一条可复制的命令。
3. **用法**：最常见的一两个场景的真实例子。库给代码示例，服务给一个请求示例，CLI 给一条命令和它的输出。
4. **配置**：环境变量用表格，列「变量 | 必填 | 默认值 | 说明」。默认值从代码里取。
5. **开发**：测试、lint、类型检查、构建命令；怎么只跑一个测试。
6. **项目结构**：只在目录不直观时写，每个目录一行说明，只列重要的。
7. **更多文档**：API 文档、架构文档、用户手册的链接。
8. **贡献 / 许可证**：仓库里有 `CONTRIBUTING`、`LICENSE` 才写，一两行加链接。

徽章（CI 状态、覆盖率、版本）只在对应服务真实存在时加，不加装饰性徽章。截图只用仓库里已有的图片或用户提供的；没有就不放，不要写一个指向不存在文件的图片链接。

### 例子

不好的开头：

> 🚀 **Invoice Service** 是一款强大的、一站式的发票管理解决方案，致力于为企业赋能，助力财务数字化转型！

好的开头（虚构项目，仅示意写法）：

> Invoice Service 负责开票、作废和红冲，供订单系统和财务后台调用。它从订单服务拉取已支付订单，按税率配置生成发票，再推送到税务平台；本地开发需要 PostgreSQL 15 和一个 Redis。

## 更新 README

1. 通读现有 README，记下它的结构、语气、术语、emoji 与格式习惯。
2. 找出变化：用户描述的改动、`git diff`、`git log -p --since=<上次更新> -- <相关路径>`。README 本身的最后修改时间可以用 `git log -1 --format=%ad -- README.md` 查，之后的提交都是候选。
3. 用下面的「变更映射」确定要动哪些章节。
4. 逐条核对现有 README 里的每条命令、每个环境变量、每个版本号是否还成立，过时的改掉或删掉。
5. 保持原有风格。原文用 emoji 的继续用，原文用英文标题的继续用英文标题。新增内容和原文读起来要像一个人写的。
6. 缺失但重要的章节（例如没有环境变量说明）可以补，补之前在交付说明里说明为什么补。

## 变更映射

| 代码里的变化 | README 里要看的地方 |
|---|---|
| 新增 / 删除依赖、升级运行时版本 | 前置条件、安装 |
| `package.json` scripts、`Makefile` 目标变化 | 快速开始、开发 |
| `.env.example` 或代码读取的环境变量变化 | 配置 |
| `docker-compose.yml`、依赖服务变化 | 快速开始（要先起哪些服务） |
| 新增 / 删除路由、命令、公开 API | 用法、功能概述、API 文档链接 |
| 端口、默认地址变化 | 快速开始里的访问地址 |
| 目录重组、包拆分或合并 | 项目结构、monorepo 子包地图 |
| 新功能上线、旧功能下线 | 功能概述、用法；下线的要删掉，不要只加不减 |
| 许可证、贡献流程变化 | 许可证、贡献 |

同一个改动如果还影响 API 文档或用户手册，一并提醒用户，或者按对应参考文件一起更新。

## 常见问题

- **README 写成了架构文档**：README 里的架构说明控制在一段话加一张简图以内，细节链接到架构文档。
- **把所有环境变量都列进来**：只列运行需要配置的；内部调试用的开关放到开发文档里。
- **快速开始跑不通**：最常见的原因是漏了前置服务（数据库没起）、漏了迁移、漏了 `.env` 复制。按一个全新环境的视角从头走一遍步骤。
- **只加不删**：删掉已经不存在的命令、参数和功能描述，比加新内容更重要。
