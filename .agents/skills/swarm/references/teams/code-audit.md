# 团队模式 · 代码审计

> 六个团队模式之一，只在命中时读这一个。

**适用**：PR review、上线前体检、安全/性能/正确性专项审计、接手陌生代码前的摸底。

**不适用**：只想知道某段逻辑怎么工作（一个 `Explore` subagent 就够）；审计完还要立刻改（审计与修复分成两个阶段，见规则 6）。

---

## 机制建议：按规模选，别默认开团队

| 范围 | 机制 |
|------|------|
| ≤10 个文件 / 单个 PR | **并行后台 subagent**，一个视角一个，lead 合成。开团队是浪费 |
| 全库 / 上百文件 / 每个文件都要过同一套检查 | **动态 workflow**（提示词里写 `ultracode`）。脚本按文件扇出，再派一个 agent 交叉验证发现——这是 workflow 的主场 |
| 审查者要互相质疑、多轮追问、边审边让实现者解释 | **agent team** |

---

## 角色

| 角色 | 载体 | 模型 | 关注面 |
|------|------|------|-------|
| **lead** | 当前会话 | — | 去重、排优先级、裁决分歧、合成总报告 |
| **security-reviewer** | `Explore`（只读） | `sonnet`+ | 认证授权、注入、密钥泄露、越权、SSRF、依赖漏洞 |
| **performance-reviewer** | `Explore` | `sonnet` | 查询与 N+1、打包体积、渲染与重排、缓存缺失、同步阻塞 |
| **correctness-reviewer** | `Explore` | `sonnet`/`opus` | 边界条件、错误处理、并发与竞态、状态机漏洞、空值 |
| **contract-reviewer** | `Explore` | `sonnet` | API 契约与向后兼容、数据模型迁移、公开类型变更 |
| **test-coverage-reviewer** | `Explore` | `sonnet` | 覆盖缺口、关键路径无测试、测试是否在测真东西 |

按任务取舍视角，不要每次全上。

> `Explore` 作为审查载体很合适（`Write`/`Edit` 被拒，锁得住），但它**不加载 CLAUDE.md**。如果仓库约定对判定有影响（「所有查询走 ORM」「禁止直连外部 API」这类），把这些规则抄进审查者的提示词，否则它会漏报一整类问题。

---

## 铁律

1. **审查者一律只读**，不给 `Write`/`Edit`/`Bash`。「顺手修一下」会让几个审查者同时改同一批文件，冲突掩盖真问题；而且改完的代码就不再是大家正在评审的那份代码。发现问题 → 报告 → 由实现者统一改。
2. **每条问题必须带 `文件:行号` + 为什么是问题 + 建议改法 + 严重度。** 没有定位的意见无法执行，也无法验证是否修好。
3. **严重度口径由 lead 在派发时定死**（P0 阻塞上线 / P1 必须修 / P2 应该修 / P3 可选）。不定口径，每份报告里的「高优先级」不是一个意思。
4. **先切范围再动手。** 明确告诉每个审查者「你只看这块，别的视角有人负责」。不切范围的结果是五个人报同一条问题、漏掉另外二十条。
5. **lead 合成时去重并交叉验证。** 同一根因被多人报出要合并；只有一人报出的高危项，派第二个 agent（最好换个模型）复核后再定级。
6. **审计与修复分阶段。** 审计团队收尾出报告；修复另起（功能开发团队或 `/batch`）。混在一起会让审查者变成实现者，失去独立视角。

---

## 输出契约

每个审查者交：

```
## <视角> 审计报告
结论：通过 / 有条件通过 / 打回

| 严重度 | 位置（文件:行号） | 问题 | 影响 | 建议改法 |
|--------|------------------|------|------|---------|

未覆盖范围：<明确说出没看什么、为什么没看>
```

「未覆盖范围」这一栏是诚实性的关键——它让 lead 和用户知道这份报告**不能**为什么背书。省掉它，一份只看了三个目录的报告会读起来像全库体检。

---

## 规模

3–6 人，由视角数决定。

---

## 常见失败

| 症状 | 处理 |
|------|------|
| 审查者顺手改代码 | 载体用 `Explore`，或在自定义定义里 `disallowedTools: Write, Edit, Bash` |
| 报告没有行号，无法定位 | 输出契约里写死引用格式 |
| 五个人报同一条问题 | 派发时切范围，合成时去重 |
| 只报问题，不报没看的地方 | 强制「未覆盖范围」栏 |
| 审计完直接开始改，范围失控 | 分阶段，修复另起团队 |
